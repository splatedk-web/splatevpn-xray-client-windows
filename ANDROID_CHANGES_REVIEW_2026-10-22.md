# Сверка Android и Windows — 22 октября 2026

После этой сверки перечисленные недостающие функции реализованы в Windows 2.13.0: SmartDNS через VPN, фоновый failover, профили с откатом, расширенный очищенный отчёт, восстановление настроек и LAN-инструкции. Таблица ниже сохраняет состояние **до переноса**, для версии 2.12.9. Результаты нового выпуска — `tests/SandboxQA/QA-2.13.0.md`.

Проверены текущие исходники соседнего проекта `../SplateClient`, включая незакоммиченные изменения, а не только последний коммит. Исходники Android и Windows при этой сверке не изменялись. Предыдущие пакеты Windows 2.12.9 не пересобирались.

## Важные детали новых SmartDNS-функций

`dns_vpn`: цепочка клиент → выбранный VPN → SmartDNS-реле → AI. Это отличается от обычного VPN: конечный выход остаётся выходом реле SmartDNS. Адрес реле разрешается на клиенте (`ForceIPv4`) до передачи в VPN через `dialerProxy: proxy`; иначе VPN-сервер мог бы разрешить исходное имя в обычный адрес AI. DoH выбранного AI-провайдера также направляется в VPN. AI-фрагментация в этом режиме не применяется; параметры транспорта VPN сохраняются. QUIC для AI блокируется. Ручной автоподбор скрыт, поскольку он проверяет только прямой SmartDNS.

Фоновый монитор: только подключённый VPN + прямой `dns_ai` + физическая сеть. Интервал пять минут, бюджет цикла три минуты. Сбой подтверждается повторно через 15 секунд. Замена должна дважды улучшить одно и то же неисправное направление без ухудшения работающих. Перед применением старый провайдер проверяется ещё раз. CAPTCHA, вход, HTTP 401/403/429 не считаются поводом менять DNS. Изменение сети/режима/провайдера и отключение отменяют проверку; применение повторно сверяет настройки. Замена сохраняет провайдера и фрагментацию вместе и кратко перезапускает VPN. Полные импортированные JSON исключены из мониторинга.

Основные источники: Android `data/AiDnsFailover.kt`, `data/AiDnsAutoSelector.kt`, `data/SettingsManager.kt`, `vpn/SplateVpnService.kt`, `vpn/XrayConfigGenerator.kt`, `ui/screens/SettingsScreen.kt` в `app/src/main/java/com/danieldk/splatevpn/`.

## Что не следует переносить автоматически

- Android включает sniffing при `enableSniffing || isFakeDns || useSmartDns || adBlocker`. Поэтому выключенная пользовательская настройка не обязательно означает выключенный sniffing в ядре. Это подтверждённое расхождение настройки и эффективной конфигурации; новую функцию нужно переносить с явной семантикой переключателя. Windows уже учитывает пользовательский выбор.
- Windows в глобальном режиме принудительно использует обычный VPN для AI. Простое добавление `dns_vpn` в список вариантов не сработает: текущие нормализатор и генератор заменят его на `vpn`. Нужно согласованно менять модель, UI, миграцию, генератор, активный статус и проверки. Смысл глобального режима должен оставаться понятен пользователю.
- Исправление DNS от 22 октября в Android убирает посторонние Google/Cloudflare fallback и ограничивает RU DNS через `skipFallback`. Windows уже использует scoped RU/AI DNS с `skipFallback` и `disableFallbackIfMatch`, без безусловного добавления этих двух резервов. Повторно копировать старую схему не требуется.
- В DNS leak test следует различать резолвер и транспорт запроса. Новый режим не обещает выход через страну выбранного VPN на конечном AI-сервисе: после VPN стоит SmartDNS-реле.
